LLM Microservices Deployment Lab

This README describes how to start the lab environment, deploy Kubernetes resources, and verify that the LLM microservice is running correctly.

Start the Lab (Privileged Mode)

The lab must be started in privileged mode:

sudo kathara lstart --privileged

Kubernetes Cluster Verification

Verify that the Kubernetes cluster is up and running.

kubectl get nodes
watch "kubectl get nodes"


Check that system pods are running:

kubectl get pods -A
watch "kubectl get pods -A"


2. Deploy Namespaces

kubectl apply -f /shared/clustera/ns.yaml
or
kubectl apply -f /shared/clusterb/ns.yaml

Verification
kubectl get namespaces

3. Deploy PersistentVolumeClaim (Cluster A)

Deploy the PVC used to access the shared LLM weights:

kubectl apply -f /shared/clustera/pvc.yaml
or
kubectl apply -f /shared/clusterb/pvc.yaml

Verification
kubectl -n llm-ns get pvc

4. Create Services

Deploy the Service resource exposing the microservice:

kubectl apply -f /shared/clustera/svc.yaml
or
kubectl apply -f /shared/clusterb/svc.yaml

Verification
kubectl -n llm-ns get svc -o wide

5. Deploy the LLM Microservice (Deployment)

Create the Deployment for the LLM microservice:

kubectl apply -f /shared/clustera/deploy_llm.yaml
or
kubectl apply -f /shared/clusterb/deploy_llm.yaml

Verification
kubectl -n llm-ns get deploy -o wide

# Check all pods in the namespace:
kubectl -n llm-ns get pods -o wide

# Get pod logs:
kubectl -n llm-ns logs -f <pod-name>

# Deleate a pod:
kubectl -n llm-ns delete pod <pod-name>

# Force the deployment to restart:
kubectl -n llm-ns rollout restart deployment llm-dply


Inspect the running Pods:

kubectl -n llm-ns get pods -o wide

6. Inspect Services

Get detailed information about a Service:

kubectl -n llm-ns describe svc

7. Create Ingress

Deploy the Ingress resource to expose the service via HTTP:

kubectl apply -f /shared/clustera/ing.yaml
or
kubectl apply -f /shared/clusterb/ing.yaml

Verification
kubectl -n llm-ns get ingress -o wide


Inspect the Ingress configuration:

kubectl -n llm-ns describe ingress llm-ing

8. Testing the Microservice

Send a test request to the /completion endpoint:

curl -X POST -H "Content-Type: application/json" \
-d '{"query":"An orc wanted to destroy everything"}' \
http://clustera.com/completion

or

curl -X POST -H "Content-Type: application/json" \
-d '{"query":"An orc wanted to destroy everything"}' \
http://clusterb.com/completion

The response should be JSON containing a short story generated by the LLM, starting with the correct prompt.

9. Monitor the Deployment

Continuously monitor all resources in the namespace:

watch "kubectl -n llm-ns get all -o wide"

Troubleshooting

check where ingress-nginx containers is running:

kubectl -n ingress-nginx get pods -o wide
